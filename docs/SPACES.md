# Space layout and switching (Phase 3a)

_Moved from CLAUDE.md on 2026-11-15. The rules most tasks need are summarised in [CLAUDE.md](../CLAUDE.md)._

- **Layout, top to bottom** (`MainViewController.setupUI`): search field → Favorites grid (`PinnedTabsView`, **outside** the swipe clip: it belongs to the profile) → swipe clip [`SpaceHeaderView`, scheduled links, the pinned list, "+ Add from Clipboard" row (`IconTitleButton` `.listRow`)] → `SpaceBarView`. No top bar.
- **Space bar** (`Components/Spaces/SpaceBarView`): gear (Settings), one `SpaceBarButton` per space (`SpaceIconView`: icon or colour dot; native tooltip = name; right-click = space menu), `+`. Centred while they fit, then scrolls horizontally with faded edges; the selection is a separate pill view (it slides during a transition). Registered with `SwipeGestureService.addExcludedView`.
- **Space header** (`SpaceHeaderView`): the current space's icon and name, aligned with list rows. Double-click renames (all renames go through it: `beginSpaceRename`, the new-space flow); click the icon for the picker (`IconPickerKind.space`: no Favicon tab); right-click for the menu.
- **Space menu** (`SpaceMenu.build`): `ClosureMenuItem`s that capture the space id, so it never switches space; `autoenablesItems = false` (otherwise a disabled item is re-enabled). Dispatch tests: `SpaceMenuTests`.
- **Settings** is not a space: `AppModel.showSettings()` / `closeSettings()` (runtime, keeps the selected space). Gear toggles, ⌘, opens, Esc closes; ⌘⌥←/→ and swipes do nothing there; creating a space closes it. The agent API reports no current space while it's shown.
- **Switching spaces** (`MainViewController+SpaceTransition`, `SpaceTransition`): a swipe, a space bar click and ⌘⌥←/→ all go through it (`requestSpaceSwitch(to:)` for clicks and keys; never call `model.selectWorkspace` for user navigation). Images of the current page and of the target move together on `SpacePageStage` (a layer-hosting view over the page; the live page is hidden meanwhile), 1:1 with the finger; on release `SpaceSwipe.outcome` decides (past 30% of the width, or a ≥ 300 pt/s flick in the drag direction; a flick back stays) and a critically damped `CASpringAnimation` settles, starting at the release speed capped at ω × remaining (no overshoot). Rubber band at the ends. Background colour, the bar's pill and (across profiles only) the Favorites' opacity follow the same progress and spring. Instant from Settings or to the current space.
- **Transition rules:** model reloads are held while a transition runs (`reloadHeldByTransition`) and run once on landing; any click or key lands a running transition first (local event monitor), because AppKit still hit-tests the old page; **never move an AppKit view by its layer transform**: AppKit can reset the transforms of its views' layers (it flashed the old list when a switch landed), so pages are plain layers on the stage and the bar's pill moves by frame plus an additive animation (`SpacePageStageTests`); the target's image is rendered in the real views without touching the model; on landing the live page is reloaded and drawn under the stage, which then fades (click-through); a switch lands with the list at the top; Reduce Motion (read per transition) crossfades instead. Tuning: `ThemeConstants.SpaceTransition`. Pure logic and tests: `SpaceSwipe`, `SwipeVelocityEstimator`, `SpaceSwipeTests`.
- **Favorites grid:** columns adapt to the width (`PinnedTabsView.columnCount`: tiles ≥ `pinnedTileMinWidth`, at least 3: 3 at the default 340-pt sidebar, 4 from ~412, 5 from ~512); rows grow to fit. `Profile.maxFavorites` is a literal 12, independent of the layout. Tiles: `pinnedTileSpacing` gaps, `CornerRadius.large`, browser-override badge in the top-trailing corner. A live-tab dot (Phase 2b) was designed and shelved on 2026-11-15: nothing polls browsers; tabs are only looked up on a click.
