# Profiles, Favorites and browser routing

_Moved from CLAUDE.md on 2026-11-15. The rules most tasks need are summarised in [CLAUDE.md](../CLAUDE.md)._

- **Favorites** are the tile grid at the top (`PinnedTabsView`), stored on the space's **profile**, so all spaces in a profile show the same grid. `pinLink` moves a list link into the current profile's favorites and cancels its scheduled reminder (the scheduler only watches space lists); `unpinLink` moves it into the *current* space's list (as in Arc), without a reminder. Async updates (favicons) find a favorite in any profile.
- **Where a link opens:** `BrowserManager.resolveTarget(link:profile:)` → link override → profile's browser → global default (`UserDefaults`). A browser that isn't installed is skipped (next level applies). The browser profile dir is `profile.browserProfiles[browser]` only when the browser is the profile's own; an override to another browser opens without one. Notes open like links without an override (the space's profile). The global browser picker sets the global default.
- **Link URL and browser validation** (`BrowserManager.validatedLinkURL`): a link is an absolute URL with a scheme. http/https need a host, `file:` a path; any other scheme (`mailto:`, `obsidian://`, `slack://`, …) is allowed except `blockedLinkSchemes` (`javascript:`, `data:`, `blob:`, `about:`, browser-internal schemes, and `x-man-page:`/`telnet:`, which open Terminal with crafted arguments). The agent API reports `bad_url` otherwise. Only http/https URLs go to a browser (and its argv, `launchArguments`); everything else opens with the system handler (`openOutsideBrowser`), ignoring browser overrides and tab focus, and a `file:` URL to an app, script, executable or launcher document (`.terminal`, `.fileloc`, `.webloc`, `.workflow`, installers; `runnableFileExtensions`) is revealed in Finder instead of opened, checking an alias's or symlink's target too. Imports keep every link; a blocked or relative one is never opened (a click beeps). Pasting one URL with an app scheme that an installed app handles (or a `file:` URL to an existing file) creates a link; other pasted text without a web URL becomes a note. **New Link…** (list background menu; **New Link in Folder…** on folders) and **Edit URL…** share one prompt that accepts `BrowserManager.typedLinkURL`: a bare host gets `https://` (`http://` for `localhost` and IPv4 addresses), and an invalid entry is asked again with the text kept. Profile and per-link browser choices must be registered HTTP(S) browsers; the agent API reports `bad_browser` for other bundle IDs.
- **Deleting a profile** moves its spaces to the first remaining profile and merges its favorites there (dedupe by `URLNormalization.key`, cap 12); what doesn't fit goes into a "Favorites (from <name>)" folder. The last profile can't be deleted. New spaces join the current space's profile.
- **Never drop links:** migration, profile deletion and Arc import all use `Profile.appendFavorites`, which returns the leftovers; callers put them in a folder.
- **UI:** Settings › Profiles (`ProfileSettingsView`: browser and browser-profile pickers, rename/delete); space menus › Profile ▸; link/favorite menus › Open in ▸ / Always open in ▸ (`BrowserMenus`); an override shows the browser icon as a badge (warning symbol if the app isn't available as a browser).
- **Browser-profile detection** (`BrowserManager.detectProfileList`) returns found / `accessDenied` / unavailable, from Chromium's `Local State` (Chrome, Chrome Canary, Helium only). Firefox browser profiles are **not supported** (removed on 2026-11-14: macOS app-data protection blocks reading `~/Library/Application Support/Firefox`); a Firefox profile *browser* works, without a browser profile. On macOS 27 every browser folder checked (Firefox, Chrome) is protected, so detection normally returns `accessDenied` unless SidebArc has Full Disk Access; the expected path is "Enter Profile…" with the folder name from `chrome://version` (last part of *Profile Path*). Opening with `--profile-directory` doesn't need to read the folder. Profile links launch through LaunchServices as a new instance (`NSWorkspace.openApplication`, `createsNewApplicationInstance`, arguments = profile switch + URL); **never spawn the browser executable as a child process**: macOS attributes the child's privacy checks to SidebArc, so a closed Chrome exits at once (status 21) with no window, crash report or log. Tests use a temp `supportRoot`, never the real folders.
- **Arc import** maps each Arc profile (`space.profile`, `topAppsContainerIDs` pairs) to the fork profile with the same name ("Default" for Arc's default) and imports its favorites (`AppModel.applyArcImport`).
- **Agent API v2** (`NoteServer`, `skills/sidebarc`): `/api/profiles` (list, create, patch name/browser; no delete), `/api/profiles/:id/favorites`, `/api/favorites/:id` (move, unpin, delete), `profileId` on workspace payloads, `browser_bundle_id` on link patch. The endpoint file reports `schemaVersion: 2` (API version, not the data schema).
- **Agent API authentication**: each app launch generates a 32-byte random bearer token. `agent-endpoint.json` contains the token and is written with mode `0600`; every `/api/*` request requires `Authorization: Bearer <token>` (compared in constant time). The editor page and its `/editor/*` files are the bundled public sources and need no token; the page is served with a strict CSP (`NoteServer.editorContentSecurityPolicy`: bundled scripts and styles only, no inline code, never framed). The editor receives the token in the URL fragment (never sent over HTTP); `NoteEditor/auth.js` moves it into the tab's history state for reloads, and `editor.js` sends it on API requests. A tab from an earlier launch has no valid token and turns read-only. Accepted exposure: the opening URL (with the fragment) can stay in the browser's history and, for a browser profile, in the short-lived launch's arguments; the token changes every launch, works only on this Mac's loopback, and same-user processes can read `agent-endpoint.json` anyway. Cross-origin `Origin` headers are rejected; the exact local origin is allowed for authenticated editor writes. API `POST`, `PATCH`, and `PUT` requests require `Content-Type: application/json`.
- **API limits and note revisions**: requests allow at most 16 KiB of headers and 8 MiB of body, 32 simultaneous connections, and 15 seconds of inactivity. Note GET returns a content `revision` (SHA-256 of the text); a PUT may include the revision it is based on and is refused with 409 `note_conflict` when the note changed since. PUT without a revision stays unconditional (agent CLI). The editor sends one save at a time (edits during it are saved right after, with the new revision); on tab close it sends the last edits with `keepalive`, based on the revision an in-flight save will produce. On a conflict it keeps the local text visible and stops saving.
- **Window attachment**: the sidebar attaches to whichever of the profiles' browsers (each resolved like `resolveTarget`, so an uninstalled one falls back) or the global default is frontmost (`WindowAttachmentService.attachmentBrowserIds`); per-link overrides don't count. It doesn't switch spaces: the sidebar keeps the current space whichever browser it follows. The set is refreshed after every model reload (`MainViewController.onModelReload`) and when the default browser changes. Activation rules are the pure `activationDecision` (a browser of the set → attach; SidebArc right after one → stay; anything else → hide). Changing the set, the position or enabling attachment never hides the sidebar while SidebArc itself is in front (Settings is shown in it); position updates don't hide it either while SidebArc is active (checked with `NSApp.isActive` as well as the frontmost pid, which can lag after a live resize); after a sidebar resize it is re-placed beside the last browser frame at the new width. Accessibility is polled every 2 s while attached (`permissionPollInterval`): revoking it in System Settings sends no notification, so without the poll the sidebar stayed attached; on loss the window returns to a movable standalone one and the preference is kept. Hide reasons are logged at `.notice` (`Hide: <reason>`), other apps' ids as private. A browser instance that hasn't finished launching while another instance of it runs (the short-lived process that opens a link in a browser profile) is ignored (`isTransientInstance`); attaching to it hid the sidebar for a moment on every such link. A browser that comes to the front without a window yet (launching, e.g. from a favorite) is polled every 0.25 s for up to 10 s while it stays frontmost (`waitForFirstWindow`), then attached with a fresh window-focus observer: one registered while the app launches may never fire. Diagnose with the `attach` log category. The attached width is the user's (`attachedSidebarWidth` in UserDefaults, set by resizing while attached; default `ThemeConstants.Sizing.attachedSidebarDefaultWidth`).
